این نسخه حاصل یک ممیزی کامل امنیتی + شکار باگ عملکردی روی v12.0-golive است.

## ۱) قابلیت‌های جدید

### 🐞 سیستم گزارش باگ با پاداش (Bug Bounty داخلی)
- **پنل کاربر → سایدبار → راهنما → «گزارش باگ»**: فرم گزارش با عنوان، شدت (کم/متوسط/زیاد/بحرانی)، توضیحات و **آپلود اسکرین‌شات** (PNG/JPG/WebP/GIF تا ۵ مگابایت با پیش‌نمایش)
- کاربر سابقه گزارش‌های خود را با وضعیت (در انتظار/در بررسی/تأیید/رد/رفع)، **پاسخ تیم فنی** و نشان «پاداش فعال شد» می‌بیند
- محدودیت نرخ: ۵ گزارش در ساعت برای هر کاربر
- اسکرین‌شات‌ها در پوشه خصوصی `private-uploads/` ذخیره و فقط با **URL امضاشده (HMAC + انقضا)** سرو می‌شوند

### 🛡️ تب «گزارش‌های باگ» در پنل سوپرادمین
- کارت‌های آماری (در انتظار/در بررسی/تأییدشده/ردشده/پاداش‌داده‌شده) + فیلتر وضعیت/شدت + صفحه‌بندی
- دیالوگ جزئیات با **نمایش و زوم اسکرین‌شات**، اطلاعات کاربر و سازمان
- اکشن‌ها: شروع بررسی / تأیید باگ / رد / علامت رفع‌شده
- **پاپ‌آپ پاداش**: بعد از تأیید باگ، پاپ‌آپ «باگ تأیید شد — اشتراک یک ماهه پلن حرفه‌ای رایگان برای این کاربر فعال شود؟ [بله / خیر]» نمایش داده می‌شود؛ با «بله»:
  - لایسنس **پلن حرفه‌ای یک‌ماهه** (source=bug-reward) صادر می‌شود
  - پلن tenant به حرفه‌ای ارتقا می‌یابد (لایسنس قبلی EXPIRED می‌شود)
  - امتیاز وفاداری تشویقی + ثبت در PlatformAuditLog
  - گزارش rewardGranted=true می‌شود و کاربر پاسخ را می‌بیند

### ⚙️ تب «محدودیت پلن‌ها» در پنل سوپرادمین
- ویرایش **maxUsers / maxInvoices / maxWarehouses** هر پلن (رایگان/پایه/حرفه‌ای/سازمانی) — مقدار `-1` = نامحدود، خالی = پیش‌فرض
- ذخیره در SystemSettings (کلید `plan_overrides`) و اعمال **فوری** روی بررسی سهمیه‌ها و لایسنس‌های جدید (با کش ۳۰ ثانیه‌ای + invalidation فوری)

### 🎁 سیستم رفرال (قبلاً ۱۰۰٪ کد مرده بود — حالا سرتاسری)
- **گرفتن لینک دعوت**: `https://دامنه/?ref=HH-XXXXXXXX` → کد در localStorage ذخیره و از URL پاک می‌شود
- **فرم چک‌اوت** (خرید پلن بدون لاگین): فیلد «کد دعوت» با prefill خودکار
- **همه مسیرهای ثبت‌نام** کد دعوت را اعمال می‌کنند: `/api/auth/register`، `/api/trial/create`، `/api/payment/register-and-pay` (کد در رکورد پرداخت ذخیره و بعد از verify موفق اعمال می‌شود)
- ثبت‌نام دوست → `SIGNED_UP` + **۱۰۰ امتیاز وفاداری** برای دعوت‌کننده
- **تبدیل پرداختی** (خرید موفق پلن توسط معرفی‌شده) → مستقیم `REWARDED` (پاداش ۵۰,۰۰۰ تومان + امتیاز)
- **ویجت «دعوت دوستان»** حالا ماژول رسمی سایدبار است (گروه سیستم): آمار، دعوت با ایمیل، اشتراک‌گذاری لینک، کپی کد
- امنیت: self-referral ممنوع، refereeUserId همیشه از توکن، ایمیل باید بخورد، PATCH با state-machine یک‌طرفه (فقط مدیر می‌تواند REWARDED کند)

# 🔧 به‌روزرسانی v12.1.1 (جلسه نهایی — تعمیر قطعی پیش‌نمایش)

## ریشه واقعی «پیش‌نمایش کار نمی‌کند» و رفع قطعی

کامپوننت `PrintPreview` (دیالوگ حرفه‌ای پیش‌نمایش با انتخاب قالب + چاپ + PDF + ایمیل) در سورس اصلی **کد مرده بود — هیچ‌جا import نمی‌شد**. یعنی باگ noopener (A1-1) اصلاً فرصت اجرا پیدا نمی‌کرد چون کامپوننت هیچ‌وقت رندر نمی‌شد!

**رفع (v12.1.1):**
- `PrintPreview` حالا با `React.lazy` به ماژول فاکتورها وصل شد
- **دکمه جدید «پیش‌نمایش چاپ»** (آیکون FileText) در ستون عملیات هر ردیف فاکتور
- **دکمه جدید «پیش‌نمایش»** در دیالوگ جزئیات فاکتور (کنار چاپ سریع)
- دیالوگ تمام‌عرض با: انتخاب قالب (استاندارد A4 عمودی/افقی، فشرده، رسمی)، پیش‌نمایش زنده iframe، چاپ، خروجی PDF، ارسال ایمیل

## قابلیت جدید UX: بازیابی آخرین ماژول فعال

- اپ موقع ورود به **آخرین ماژولی که کاربر داخلش بود** برمی‌گردد (sessionStorage) — قبلاً همیشه داشبورد
- برای کاربرانی که روزانه با «فروش و خرید» یا «انبار» کار می‌کنند صرفه‌جویی واقعی در کلیک

## راستی‌آزمایی مرورگر (end-to-end)

- ورود → ماژول فروش و خرید → ردیف فاکتور 1405-000001 → کلیک «پیش‌نمایش چاپ» → **دیالوگ PrintPreview باز شد ✓**
- فاکتور با طرف‌حساب «شرکت تست چاپ»، ۲ ردیف کالا، قیمت‌ها و جمع کل در iframe رندر شد ✓
- دکمه‌های چاپ / PDF / ایمیل / انتخاب قالب همگی فعال ✓
- ماژول‌های «گزارش باگ» و «دعوت دوستان» در سایدبار ✓

# 🔧 به‌روزرسانی v12.1.2 (رفع باگ رفرال + QA نهایی)

## 🐞 باگ REF-1: قیف رفرال برای لینک عمومی گم می‌شد (بحرانی برای رشد ویروسی)

**ریشه:** ستون `code` در مدل Referral با `@unique` یکتا بود و `applyReferralOnSignup` با `findUnique({ code })` فقط «یک» رکورد را پیدا می‌کرد. در نتیجه کد رفرال عملاً **یک‌بارمصرف برای یک ایمیل ازپیش‌تعیین‌شده** بود:

- دوستی که از **لینک عمومی** `?ref=HH-XXXX` می‌آمد و با «ایمیل خودش» ثبت‌نام می‌کرد → `EMAIL_MISMATCH` → رفرال گم می‌شد، دعوت‌کننده امتیاز نمی‌گرفت
- بعد از اولین تبدیل (SIGNED_UP) → `ALREADY_TRACKED` → هیچ دوست دیگری با همان کد قابل track نبود
- هر «دعوت جدید» از ویجت کد جدید می‌گرفت → کاربر چند کد پراکنده داشت (UX غیراستاندارد)

**رفع (v12.1.2):**
1. **اسکیما:** `code` از `@unique` به عادی + `@@index([code])` تغییر کرد — کد = «کد شخصی دعوت‌کننده»، یک کد → چند رکورد دعوت
2. **`lib/referral-engine.ts` — بازنویسی کامل `applyReferralOnSignup`:**
   - مسیر A (دعوت مستقیم): رکورد PENDING با ایمیل منطبق → همان رکورد SIGNED_UP می‌شود
   - مسیر B (لینک عمومی): رکورد جدید SIGNED_UP با کد شخصی و ایمیل دعوت‌شده ساخته می‌شود
   - idempotent: هر referee فقط یک‌بار با هر کد track می‌شود (`refereeUserId` چک)
   - self-referral و referrer-inactive همچنان رد می‌شوند
   - audit log حالا مسیر ورود (DIRECT / PUBLIC_LINK) را ثبت می‌کند
3. **`app/api/marketing/referral/route.ts` (POST):** دعوت جدید از کد شخصی موجود کاربر استفاده می‌کند (کد ثابت per کاربر)؛ چک تداخل فقط برای کدهای متعلق به «کاربر دیگر»
